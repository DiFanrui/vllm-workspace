## 阶段 0：磁盘清理 + 模型下载

**目标：** 腾出 62GB 空间并下载模型。

```bash
# 0.1 删除纯文本 30B（已获用户批准）
rm -rf /data/models/Qwen3-30B-A3B-Instruct-2507

# 0.2 下载 VL-30B（modelscope，复用现有下载渠道）
# 通过 modelscope CLI：modelscope download --model Qwen/Qwen3-VL-30B-A3B-Instruct --local_dir /data/models/Qwen3-VL-30B-A3B-Instruct
# 或 hf CLI：  HF_ENDPOINT=https://hf-mirror.com huggingface-cli download Qwen/Qwen3-VL-30B-A3B-Instruct --local-dir /data/models/Qwen3-VL-30B-A3B-Instruct

# 0.3 校验
du -sh /data/models/Qwen3-VL-30B-A3B-Instruct   # 期望 ~62GB

```

**验证标准：** 模型文件齐全（config.json + 13 个 safetensors + preprocessor_config.json + tokenizer），磁盘剩余 ≥ 15GB。

## 阶段 1：双卡 TP=2 部署 + 多模态验证

**目标：** 2 卡 tensor-parallel 跑起来，验证图像/视频/文本三条链路。

```bash
# 1.1 启动双卡服务
ASCEND_RT_VISIBLE_DEVICES=0,1 vllm serve /data/models/Qwen3-VL-30B-A3B-Instruct \
  --port 8001 --trust-remote-code \
  --tensor-parallel-size 2 \
  --gpu-memory-utilization 0.9 --max-model-len 8192 \
  --limit-mm-per-prompt '{"image": 1}' \
  > /tmp/vllm_qwen3vl_30b.log 2>&1

# 1.2 健康检查
curl http://127.0.0.1:8001/v1/models

# 1.3 图像测试（用 test_0811/scripts/test_vision.py）
python test_0811/scripts/test_vision.py --image /tmp/test_red_circle.png
# 1.4 文本测试
python test_0811/scripts/test_text.py
```

**验证标准：**
- `/v1/models` 返回模型
- 图像问答正确（参考 8B 实测："红色圆形禁止标志"）
- `npu-smi info` 确认 **两张卡** 都在被 VLLMEngineCore 使用、显存各 ~55GB 量级
- 日志无 TP 相关报错，`tensor_parallel_size=2` 生效

**关注点：**
- 首次启动图编译时间长（5-15 分钟），耐心等待，不要提前判定失败
- 观察 [patch_qwen3vl.py](/vllm-workspace/vllm-ascend/vllm_ascend/patch/worker/patch_qwen3vl.py) 的 `tensor_parallel_wrap` 是否生效（deepstack ViT 输出按 TP rank 切分）

## 阶段 2：MoE 特性验证

**目标：** 展示稀疏 MoE 的特性与性能优势。

| 测试项 | 方法 | 预期 |
|---|---|---|
| 专家路由生效 | 观察日志/火焰图中的专家分发，确认 30B 总参但仅 3B 激活 | 推理延迟 ≈ 同规模稠密模型的 1/5~1/10 |
| EPLB 负载均衡 | 配置 `vllm-ascend` 的 EPLB（ascend_config），观察专家分配 | 负载均衡开启前后对比 |
| 专家并行 | `--enable-expert-parallel`（与 `--tensor-parallel-size 2` 配合，专家分布到 2 卡）对比 TP=2 不开 EP | 通信开销 vs 吞吐权衡；vllm-ascend 的 EP 内核需实测（以 DeepSeek 系验证为主，Qwen3-VL 待确认） |
| 与 8B 对比 | 同一测试集跑 Qwen3-VL-8B（单卡）vs 30B-A3B（双卡） | 30B-A3B 精度更高、吞吐接近 |

**产出：** MoE 架构讲解材料（稀疏路由、top-k 专家选择、A3B 命名含义：All ~3B active）。
